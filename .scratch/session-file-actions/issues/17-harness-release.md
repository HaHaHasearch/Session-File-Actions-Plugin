用候选发行包独立完成 Harness 的安装、功能和兼容性验收。

## 验收条件

- [ ] 在干净 Windows 受管 profile 核验按发布者与精确版本安装、tgz 安装、启用、升级、回退、卸载。
- [ ] 按 §5.1 分列上传及交付，同宿主混选；记录版本、包哈希、真实文件粘贴哈希、失败与未验证组合。
- [ ] 交付含 Host、client、组合包 patch 的预构建 npm 包、安装说明、最低实测版本与兼容表。依赖补丁时提供对应基线、可获取的补丁和可重建验证构建；核验发布身份后走授权发布流程。

## 分支、提交与合入

从两端约定的同一 `windows-one` 候选提交开 `harness-release`，记录候选提交号与包哈希。

按可验证行为提交，相关实现、测试和必要文档同次提交。提交或 PR 标题示例：`chore(harness): verify Windows release package`。合回 `windows-one` 前同步集成分支，复跑本票及受共享契约影响的验证。在 Comments 记录实际提交号、验证结果和证据位置。

两端分别验收。修复改变候选产物时记录新候选并复验受影响端；修改共享代码需重新构建、复验两端。两端正式支持组合通过后才将经过验收的集成版本合入 `main`。仅验证构建通过或必要项尚未验证时保留交付缺口。
