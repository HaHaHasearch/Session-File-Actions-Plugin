# 13 双击、默认打开与选择应用

Status: ready-for-agent

Blocked by: 05, 06, 07, 08

阶段：三 · 用户操作与生命周期

## 交付结果

单击不打开，双击仅打开被双击的附件一次；菜单支持按默认关联或选定应用批量打开。

依据：[§3](../../../doc/会话附件操作插件需求Spec.md#3-卡片和操作对象)、[§3.1](../../../doc/会话附件操作插件需求Spec.md#31-右键菜单设计)、[§4](../../../doc/会话附件操作插件需求Spec.md#4-批次反馈与生命周期)。对应验收用例 07、12。

## 验收条件

- [ ] 混合类型按会话顺序分别提交各自默认应用；共同应用子菜单去重，共同默认项置顶；没有交集时可见、禁用并说明原因。
- [ ] 选择应用一次后每项只提交一次；单项失败继续其他项，系统接收请求不冒充应用已显示文件。
- [ ] 授权本地文件打开原位置；远端或会话副本用标明的本地副本，编辑副本不改原始内容，宿主退出前保留，之后占用或状态不明延后清理。

## 分支、提交与合入

确认前置票 05、06、07、08 已合入 `windows-one` 后，从该集成分支开 `open-files`。

按可验证行为提交，相关实现、测试和必要文档同次提交。提交或 PR 标题示例：`feat(desktop-files): open selected attachments`。合回 `windows-one` 前同步集成分支，复跑本票及受共享契约影响的验证。在 Comments 记录实际提交号、验证结果和证据位置。
