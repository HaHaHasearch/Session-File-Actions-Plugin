# 会话附件操作插件 Windows 1.0 需求 Spec

2026-11-04 · 已定稿 · 适用于 DeepSeek Harness Desktop 和 OpenCode Desktop

## 1. 用户目标与范围

用户在已发送消息的原附件卡片上操作文件。最短路径是鼠标停在报告上按 Ctrl+C，切换到 Windows 资源管理器按 Ctrl+V，得到一份可打开的报告。也可以在同一会话跨消息选中报告和表格，一次复制或另存为。两端独立安装和验收。

本期不提供剪切、移动、批量导出、复制文本附件正文、独立文件管理页或跨会话选择。聊天输入框已有的文件粘贴沿用宿主行为。快捷键条款规定用户按键的效果，具体沿用或接入宿主事件的方式由实现决定。

### 1.1 最终交付物与完成条件

Windows 1.0 的正式成品是两份可独立安装的预构建 npm 包。用户按客户端安装其中一份，即可在原消息附件卡片上操作文件，无需获取源码或自行构建。

| 正式交付物 | 拟用包名 | 产物要求 | 本地验证形式 |
|---|---|---|---|
| DeepSeek Harness Desktop 插件 | `dsh-session-file-actions` | 含已编译的 Host 与 client 入口，以及清单声明的组合包 patch，可在目标桌面 profile 启用 | 可直接安装的 `.tgz` 组合包 |
| OpenCode Desktop 插件 | `opencode-session-file-actions` | 清单通过 `./gui-experimental` 导出已构建的桌面 GUI 入口，可由桌面自带的后台服务器加载 | 可解压并按目录注册的同一包内容 |

**随版本交付的资料。** 发布页列出发布者、实际包名、与宿主匹配的完整安装字符串（包名@精确版本），并提供本节的安装、升级、回退及卸载说明。兼容表逐端列出插件版本、最低实测宿主版本、官方发行版或带补丁验证版，并关联对应的 Windows 验收记录。表中两个包名尚未确认归属或发布，安装时以正式发布页为准。

**宿主需要补丁时。** 若官方发行版尚缺必要接口，验证交付须同时提供匹配的宿主验证构建和插件包，标明上游基线、补丁及重建说明。该组合通过的验收只适用于列明的验证构建。若上游最终未提供所需能力，是否正式维护和分发自有宿主构建需另行决定。

**完成条件。** 两端分别在干净 Windows 配置中，从实际交付包完成安装、升级和卸载，并通过第 5 节中适用于该宿主和附件来源的验收。文件复制必须从原卡片触发，在资源管理器中实际粘贴并核对文件名和内容哈希。两个正式支持的组合都通过后，Windows 1.0 才算完整交付。交付方式和版本基线见[技术路线第 1 节](./会话附件操作插件技术路线.md)。

### 1.2 Windows 插件安装说明

先查发布页兼容表。选择“官方发行版”对应的插件版本即可使用下面的正式安装入口；若该组合标为“带补丁验证版”，先安装指定宿主构建，再按其随包说明安装插件。仅更换插件安装渠道不能补齐宿主缺少的卡片接口。

#### DeepSeek Harness Desktop

1. 在正在使用的桌面 profile 打开侧栏 **插件 → 添加插件**。该入口需要受管 profile。
2. 粘贴发布页为该宿主提供的 **包名@精确版本**，点击**安装**，核对实际包名、来源和版本。使用桌面内的入口，可避免误装到独立的 web profile。
3. 安装完成后点击**立即启用**，或从**已安装插件**打开组合包开关。按宿主提示重启，再到同一 profile 的会话卡片验证。若失败，展开**查看安装详情**，区分安装失败和启用失败。

**本地验证包。** 同一输入框也接受预构建组合包的绝对路径，例如 `D:\Downloads\session-file-actions-harness.tgz`。路径须能被当前 Host 读取。选择该文件后沿用上述启用和验证步骤。

**升级和卸载。** 在目标 profile 的插件详情中移除第三方旧包，再用兼容表指定的新版本或新版 tarball 安装并启用。回退时同样装回原先实测的版本。仅关闭开关会保留已安装的包。[固定基线的安装界面](../upstream/deepseek-harness/packages/client/ui-plugin-manager/README.zh.md) · [社区实例 dsh-market](https://github.com/dsh-market/dsh-market#install)

#### OpenCode Desktop

1. 打开 Windows 当前用户的全局配置，默认是 `%USERPROFILE%\.config\opencode\opencode.json` 或 `opencode.jsonc`。沿用现有文件；尚无配置时可创建 `opencode.jsonc`。
2. 将发布页给出的 **包名@精确版本**追加到 `plugins` 数组，保留已有插件和其他字段。下例中的 `<版本>` 须替换为兼容表中的实际版本：

```json
{
  "plugins": ["opencode-session-file-actions@<版本>"]
}
```

3. 保存后重新打开 OpenCode Desktop，在 **Settings → Extensions → Plugins** 选择应用自带的后台服务器，确认插件已列出且 GUI 开关已打开。加载失败时核对包版本、兼容宿主与配置位置，修正后点 **Reload**。仅配置 TUI 的 `cli.json` 不会加载桌面 GUI。

**本地验证包。** 将预构建包解压到固定目录，如 `D:\Plugins\session-file-actions-opencode`。该层应直接包含 `package.json` 和其 `exports["./gui-experimental"]` 指向的已编译文件。在同一全局数组中使用 `file:///D:/Plugins/session-file-actions-opencode` **替代**包名条目，同一个插件只登记一次。使用期间保留该目录。

**升级和卸载。** 在原条目更换精确版本；本地验证包则将新版解压到新目录，把原 URI 改指新版。重开应用后复核，回退时恢复旧条目。卸载时仅移除本插件条目，重载后检查列表。设置页的开关只停用桌面 GUI。[固定基线的包来源与桌面安装说明](../upstream/opencode/services/www/src/docs/content/plugins.mdx) · [桌面 GUI 加载约定](../upstream/opencode/services/www/src/docs/content/build/plugins/gui/index.mdx) · [社区实例 opencode-github-panel](https://github.com/neriousy/opencode-github-panel/blob/c8fb7c9297c3954d07446250cbfeb957e514475c/README.md#install)

#### 验证安装结果

在目标宿主选一份已知内容的文件附件，右键选择「复制文件」，切换到 Windows 资源管理器的空目录按 Ctrl+V，核对文件名与内容。发布验收还须比对 SHA-256，并按[需求 Spec §5](#5-两个宿主分别验收)分别验证两端。安装列表有记录只说明宿主识别了包，原卡片操作和实际粘贴要单独核对。

## 2. 点击哪张卡片，取得哪份文件

宿主按当前调用者的权限，从宿主实例、会话、消息和附件在消息中的位置确定对象。显示名相同、字节相同或路径相同的两次出现仍可分别选择。仅有预览、普通文本链接或尚无持久身份的本地回显不提供文件动作。

| 宿主记录 | 用户得到的内容 |
|---|---|
| 有明确关联的源路径，包括同时有会话副本 | 读取该路径在本次操作时的文件。修改后复制得到修改后的字节。移走、删除、无权限或远端不可达均报告失败，禁止改读副本、按名称搜索或使用缩略图。 |
| 没有关联源路径，有宿主保存的附件内容 | 读取当前消息引用的会话副本或可信内联原始字节。读取失败或完整性校验失败时指出对应附件。 |
| 两种来源混选 | 各自按上两行取文件，一次操作，无版本选择框。不同动作使用同一来源判断。 |

典型路径项有 Harness 工作区交付物及 OpenCode 消息中明确引用的路径。Harness 内容存储、OpenCode 媒体存储和已内联的附件字节属于会话副本。存储副本的内部磁盘位置不等于用户的源路径。远端路径由所属服务器授权读取。新旧消息均按实际记录判断，本期无需为了复制路径附件而改变发送流程或新增快照。

## 3. 卡片和操作对象

| 编号 | 用户动作及应观察到的结果 |
|---|---|
| F01 | 悬停原附件卡片，在卡片旁显示文件路径提示（§3.2）。若卡片已有独立复制按钮，无论卡片是否已选，点击该按钮只复制所在卡片的附件，原选择保持不变。悬停本身不改变选择，不自动弹出右键菜单。普通左键单击只选中该附件并设为锚点，不打开文件。双击只打开被双击的附件一次。 |
| F02 | 无需先左键选中。右键已选项保留集合和原锚点，菜单作用于整个集合。右键未选项时只选中该项，并将它设为新锚点。单选与多选提供相同的六条命令，顺序与分组见 §3.1。 |
| F03、F04、F06 | 菜单「复制文件」和附件上下文的 Ctrl+C 执行同一复制。在附件上下文按 Ctrl+C，有任何选中项就复制整个选中集合（包括只选一项），鼠标移到未选卡片不改变目标。无选中项时复制悬停附件；既无选择也无悬停时，若键盘焦点在附件上，则复制焦点项。输入框、编辑器或文本选区优先于附件；离开附件上下文后历史选择不截获按键。成功后可用 Windows 粘贴操作取得真实文件。 |
| F05 | Ctrl+单击增减一项，Shift+单击从锚点选到目标，按消息及消息内附件顺序取连续区间。连续 Shift 选择沿用同一锚点，用新范围替换旧范围。普通单击或 Ctrl+单击均以本次点击的位置为锚点，即使该项刚被取消选中。无锚点时 Shift+单击只选目标，并以它建立锚点。附件上下文的 Ctrl+A 选择整个当前会话的可操作项。顺序不完整时先向宿主取齐，失败则提示并保留原选择。滚动、重绘保留选择。Esc、切换会话、刷新和卸载清空选择与锚点。 |
| F07 | 单项「另存为…」选择名称和位置；多项只选一次目录，按会话顺序平铺。已有文件及同名项都保留，新文件用可识别后缀，并显示实际保存名。例如单项指定「报告.pdf」时若已有同名文件，则保留原文件，保存为「报告 (2).pdf」并提示实际名称；若仍重名则递增。 |
| F08 | 已取消，保留编号。界面和验收均不设导出命令、分类子目录或清单。 |
| F09、F10、F11 | 单选和多选均可用各文件的默认应用打开、选择共同适用的应用打开，或在资源管理器定位全部选中文件。能直接访问的授权本地源文件用原位置。远端文件和会话副本在本机准备副本，操作时标明“本地副本”；外部编辑不能改坏会话保存的字节。 |
| F12 | 复制实际可访问的本地路径为纯文本，多项按会话顺序逐行排列。全部路径准备成功后一次写入文本。某项失败则指出该项及原因，整批停止并保留原剪贴板。有临时副本时提示路径用途及保留条件，用户可另存为取得永久位置。 |

### 3.1 右键菜单设计

右键按下的位置决定本次菜单的对象。右键未选中的 C 时只高亮 C；右键已选中的 A 时保留 A、B 的高亮。打开菜单时固定这些附件的身份；鼠标移过另一张卡片不会更换目标。菜单从上到下按下图排列。左侧是单选菜单展开「打开方式」的状态，右侧是多选菜单，上下两组分别展示深色与浅色主题。

![附件右键菜单设计稿：单选、打开方式子菜单与多选](./附件右键菜单.svg)

| 顺序 | 单选一份文件 | 多选两份文件 |
|---|---|---|
| 1 | 打开文件 | 打开文件 |
| 2 | 在资源管理器中定位 | 在资源管理器中定位 |
| 3 | 打开方式　› | 打开方式　› |
| 分隔 | 一条横线 | 一条横线 |
| 4 | 另存为… | 另存为… |
| 5 | 复制文件　Ctrl+C | 复制 2 个文件　Ctrl+C |
| 6 | 复制文件路径 | 复制 2 个文件的路径 |

**主菜单。** 采用参考图的上下两组布局。「打开文件」直接用默认关联应用打开。「在资源管理器中定位」使用文件夹图标，打开目录并选中对应文件；远端附件按 F11 定位到准备好的本地副本。「另存为…」单选时选名称和位置，多选时只选一次目录。「复制文件」发布文件列表，「复制文件路径」发布路径文本。多选沿用同一打开组和分隔线，复制命令的数量取本次操作对象数。文件操作组不引入参考图中的「复制文件内容」。

**打开方式。** 鼠标停在整行、点击该行或按向右方向键均可展开子菜单，只展开不启动应用。子菜单贴主菜单右边，与触发行上沿对齐；向子菜单移动时父行保持高亮。子项按“应用图标＋本机应用名称”排列，所有操作对象的默认应用相同时，该应用排首位并标记“默认”，同一应用只列一次，点击或按 Enter 才用它打开文件。图中的应用名是示例，实际只列宿主能启动并能打开每个选中文件的应用。文件夹定位只在主菜单出现一次。没有适用应用时按下述禁用规则展示。

**主题（验收要求）。** 单选菜单、多选菜单和「打开方式」子菜单均使用当前宿主窗口实际生效的主题。宿主指定浅色或深色时，即使 Windows 配色不同也以宿主为准；宿主设为跟随系统时，菜单随宿主一起切换。面板底色、文字、边框、分隔线、悬停、禁用和焦点色成套取自同一主题。运行中主题改变后，仍可见的菜单同步更新，新打开的菜单立即使用新配色，无需重启插件。

**视觉尺寸（设计建议）。** 参考图的深色外观采用近黑面板（约 #202020）、浅色文字（约 #F2F2F2）、整行灰色高亮（约 #363636）及单条细分隔线。主、子菜单使用同一面板样式、约 8 px 圆角和轻阴影。按 100% 缩放设计，行高约 36 px，字号约 14 px，左右留白约 12 px，图标约 18 px，图标与文字间隔约 10 px。无图标的行保留图标列，使所有命令文字左缘对齐；箭头和快捷键提示固定在行尾。宽度按最长标签、数量及快捷键自适应。图中色值仅供示意；宿主启用高对比度时沿用其可读配色。

**定位与状态。** 主菜单靠近触发点，右侧不足时子菜单向左展开，上下越界时移入可视区；应用列表超过可视高度时仅列表滚动。普通、悬停、键盘焦点和禁用分别可辨，键盘焦点采用宿主可见轮廓。卡片的选中高亮保持独立，移过菜单行不改变操作对象。

**多选命令的执行规则。** 「打开文件」按会话顺序为每项调用各自默认应用，各提交一次。「打开方式」只选一次应用，用它打开全部所选项；无共同适用应用时保留禁用项并说明原因，用户仍可按各自默认应用打开。「在资源管理器中定位」按实际本地父目录分组，每个目录展示一次并同时选中该组文件；远端附件先准备本地副本。打开或定位遇到单项失败时继续其余可处理项，列出失败项和原因；已提交给系统的打开请求不等同于应用已显示文件。

- **可用状态。** 单选和多选均保留六条命令。适用命令若已知缺少桌面能力，保留禁用态并给出可用键盘读取的原因；没有可选应用时同样说明。打开菜单无需下载附件或改写剪贴板。执行时再核验来源和权限，发现路径失效则关闭菜单并在原会话反馈失败项，不静默改读历史副本。宿主原有的非重复操作保留在独立分组，可复制图片时仍明确区分「复制图片」和「复制文件」。
- **键盘与关闭。** 有卡片焦点时，菜单键或 Shift+F10 对该卡片执行与右键相同的选取规则。上下键移动焦点，右键展开子菜单，左键返回上级，Enter 执行当前可用命令。Esc 先收起子菜单，再关闭主菜单；菜单关闭后再按 Esc 才清空附件选择。点菜单外空白处只关闭菜单。取消后焦点回到触发卡片，保持打开菜单时的选中集合。
- **执行与反馈。** 选定命令后先关闭菜单，只发起一次操作。另存为的对话框取消时不写文件；切换会话时关闭旧菜单，不能在新会话执行旧命令。成功、失败、取消和结果未确认按第 4 节反馈，关闭菜单本身不显示操作成功。

### 3.2 悬停路径提示

鼠标停在附件上时，紧邻卡片显示圆角文字浮层，沿用当前宿主的深浅主题。完整路径过长时按可用宽度换行，保留路径分隔符和文件名。移出卡片或打开右键菜单时收起提示。悬停不改变选择或剪贴板。

提示展示当前会话有权显示的关联路径。远端路径标明“远端”；只有会话副本时显示“会话副本 · 无源文件路径”。路径来自附件记录，显示它不代表文件当前仍可访问。悬停不下载文件、不创建本地副本，不把宿主内部缓存位置当作源路径展示。

## 4. 批次、反馈与生命周期

- 触发时固定操作对象。复制先准备并校验全部文件，按安全的 Windows 文件名一次发布文件列表，复制不会移动或修改源文件。批内同名自动加后缀，反馈原名与结果名。复制后源文件再次修改，粘贴仍取得本次复制的内容。
- 任一项准备失败或准备中取消，整批停止，原剪贴板保留。系统确认写入后才显示已复制的数量。写入阶段出错时报告失败；无法判定写入结果时显示“复制结果未确认”。同一宿主受理新复制后，尚在准备的旧复制失去发布资格，即使新复制随后失败。
- 耗时的复制和另存为在发起会话中显示阶段、进度及「取消」，例如“正在准备 2/5 个文件”。复制进入系统发布阶段后结束取消入口。切换聊天不会取消已发起的操作，进度与最终结果归发起会话，返回该会话可查看。
- 批量另存为显示已完成数和总数。单项失败继续下一项，取消则停止后续写入。保留完整的成功项，只清理本次未完成文件。结束列出成功、失败和取消的数量及失败项原因。重试和并发保存都不得覆盖已有文件。
- 卸载时停止尚在准备的复制，保留原剪贴板；另存为停止剩余写入，只清理本次未完成文件，保留已发布的成品。已提交系统但没有回执的操作记录为“结果未确认”，不自动重放。
- 切换会话、卸载插件或退出宿主后，剪贴板仍引用的副本可重复粘贴。重启清理须确认引用已解除并经过宽限期；检查失败则保留待查。不得清理用户另存为的文件。空间不足时报告准备失败。
- F12 的临时路径在系统剪贴板仍含该路径列表时可用，包括宿主退出后。打开或定位得到的本地副本至少保留到本次宿主会话结束（切换聊天不算结束）。之后仍须经过宽限期，文件被占用或无法确认可清理时延后回收。外部编辑需长期保存时提示用户另存为。
- 用户能辨认失败项及原因，诊断记录含操作 ID、宿主、来源类别、阶段及原因，应区分授权、读取、完整性、磁盘、剪贴板发布和结果未确认。日志不含正文、凭据或完整私人路径。

## 5. 两个宿主分别验收

从实际插件包安装到对应 Windows 宿主，在原卡片执行。记录宿主与插件版本、官方版或补丁构建、来源、步骤、预期及实际结果、粘贴文件名与 SHA-256、失败阶段和未验证项。以下是待执行用例。

| 用例 | 操作及通过条件 |
|---|---|
| 01 单文件与版本 | 路径附件发出后改写为 B，原会话副本为 A。右键复制并粘贴得到 B。仅有副本的另一附件在上传原文件删除后用悬停 Ctrl+C 仍得到 A。各自核对哈希。 |
| 02 混选与同名 | 跨消息选择两个同名异内容附件，一项有路径一项只有副本。复制过程中无版本确认框，粘贴得到两份可区分的文件，两个哈希分别匹配。再以相同内容不同名验证均保留。 |
| 03 失败边界 | 预置一段剪贴板文本，把有关联路径的文件移走，保留其消息副本。与可读项一起复制，显示具体失败项，粘贴仍得到原文本。对拒绝访问、远端断连或内容损坏验证相同的准备失败语义。 |
| 04 选择与焦点 | 按会话顺序放置 A、B、C。单击 A 只选 A，Ctrl+单击 B 后选中 A、B；滚动重绘后右键 B 并复制得到 A、B。在相同选择下移到 C，不点击，按 Ctrl+C，粘贴只得到 A、B。若 A 卡片已有独立复制按钮，点它只复制 A，A、B 仍选中。若 C 卡片已有独立复制按钮，仍选中 A、B 时直接点击该卡片上的「复制文件」按钮，粘贴只得到 C。清空选择后悬停 C 再按 Ctrl+C，粘贴只得到 C。重新选中 A、B 后右键 C，只出现 C 的单文件菜单，复制只得到 C。关菜单后 Shift+单击 D（顺序 A、B、C、D）只选 C、D。另从单击 A、Shift+单击 C 开始，右键已选 B 并关闭菜单，再 Shift+单击 D，应选 A、B、C、D。双击 C 只打开 C 一次。单击 A 后 Shift+单击 C 选中 A、B、C，再 Shift+单击 B 得到 A、B。Esc 清空选择。无锚点时 Shift+单击 B 仅选 B；Ctrl+单击 B 将其移除，再 Shift+单击 C 应选中 B、C。清空选择、移开鼠标，将键盘焦点移到 A 时按 Ctrl+C 只复制 A。Ctrl+A 覆盖未显示的历史附件；历史读取失败时保留原选择。输入框或消息文本有选区时悬停附件并复制，得到文本。切换会话后核对无旧选择。 |
| 05 生命周期与系统粘贴 | 用二进制样本复制后修改源文件，先后在资源管理器、支持文件粘贴的另一款应用取得同一份字节。切换会话、退出宿主后重复粘贴；重载插件后按一次 Ctrl+C 只执行一次。 |
| 06 保存与取消 | 单项指定已存在的「报告.pdf」，核对原文件哈希不变，新文件与提示均为「报告 (2).pdf」。多项保存至已有同名文件的目录，原文件完好；中途遇到不可读项继续保存后项，取消长批次后已完成文件完好，数量可核对，无半成品。 |
| 07 系统动作 | 对本地路径项、远端项和副本分别验证默认打开、选择应用、定位、复制路径。授权本地源路径项打开的是源文件，定位与路径文本指向原位置。远端或会话副本则打开和定位标明的本地副本；编辑该副本后重新读取来源，原始哈希不变。 |
| 08 发布失败及竞争 | 模拟准备阶段空间不足和系统写入失败，核对提示与实际失败阶段。预置剪贴板文本，让早发起的复制晚完成。新复制成功时只得到新列表；新复制准备失败时仍得到原文本。另在系统写入后中断回执，应显示“复制结果未确认”，不自动重新发布。 |
| 09 范围 | 单选与多选均显示同样的六项文件命令，顺序与分隔线一致；输入框已有 Ctrl+V 接收文件的流程归宿主。Windows 接收程序不支持文件粘贴时，不承诺该程序能接收。 |
| 10 路径复制与保留 | 复制两项路径，其中一项远端不可读，原剪贴板文本保留。恢复后复制得到按顺序排列的两行路径，退出宿主后路径仍可访问。另行打开或定位副本，切换聊天后仍可访问；退出后文件仍被占用时不清理。 |
| 11 右键菜单 | 在每个宿主的普通文件卡片上对照 §3.1 核对单选和多选分组、标签及数量。在窗口右下角以鼠标和键盘分别打开菜单，命令完整可达。分别令宿主主题与 Windows 相反，核对主、子菜单跟随宿主；再将宿主设为跟随系统，切换系统主题，无需重启即可看到新配色。核对系统缩放后文字与箭头没有重叠，鼠标从父行进入子菜单时仍保持展开，点选某应用只打开一次。打开「打开方式」后按 Esc 返回主菜单，再按 Esc 关闭，原选择保留且没有文件被打开。多选后取消另存为，目标目录不变。对已失效路径执行复制，只报告失败。 |
| 12 多选打开与定位 | 选中 A.pdf、B.pdf，点一次「打开方式」并选定共同应用，两份文件各提交一次。再选默认应用不同的两份文件，点「打开文件」，各自交给对应应用。无共同应用时「打开方式」可见并说明不可用。选中同目录 A、B 和另一目录 C 后定位，前一目录同时选中 A、B，后一目录选中 C。移走 B 后重复操作，A、C 仍可处理且 B 单独报错。 |
| 13 悬停提示 | 选中 A 后悬停未选的 B，完整长路径可换行读出，A 保持选中。远端项有远端标识；仅有会话副本的项不出现伪造的本地路径。切换主题检查文字可读，打开右键菜单后提示消失。 |
| 14 进度归属与取消 | 在会话 A 复制多个文件，准备中点击「取消」，原剪贴板保留。重新发起后切换到会话 B，操作继续且结果不出现在 B；返回 A 可见结果。在 A 取消长批次另存为，已完成文件与结果计数一致。分别在复制准备中、另存为已完成首项后卸载：前者保留原剪贴板，后者保留首项且无半成品。系统调用已提交但回执未到时卸载，重载后可查“结果未确认”，不重复执行。 |

## 6. 设计取舍与实现边界

已选择单独编写 Spec，保留[历史需求稿](./会话附件操作插件需求与设计.md)供追溯。直接改写旧稿会少维护一份文档，但不易对照已取消的 F08。来源失效时，已选择显式失败；自动使用旧副本可能交付缺少最近修改的文件。公开操作仅展示「复制文件」，来源差异体现在实际取得的文件和失败原因上。
